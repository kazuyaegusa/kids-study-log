# 冒険ノート

毎日の学びをゲーム風に記録する、iPad向けの静的PWAです。アプリに依存ライブラリとビルド工程はありません。

## 画面

- ホーム: 相棒アバター、日替わりの吹き出し、EXP、炎のストリーク、今週の記録、目標リング。相棒は6体の影から選びます。画像が写るマスを優先し、月とポケモンIDを使ったランダム順で開きます。
- 記録シート: 黄色いボタンから開きます。項目をタップして複数の行を追加し、各行で分を選びます。再タップか行の×で外せます。日付と自分から、一言・疑問・写真は共通です。一言、疑問、写真は「もっと書く」で開きます。項目が0件なら保存できません。
- 保存演出: 相棒が跳ね、マスとEXPを表示。完成時は影がカラーに変わり、名前を発表します。その後「冒険クリア！」でEXP・今日の合計分数・連続日数を表示します。「続ける」でホームに戻ります。
- ポケモン図鑑: 番号、完成数、名前とカラー画像、未完成の影と進捗、10種類のバッジ、疑問の付箋。完成した相棒をアバターにできます。完成数は同じポケモンを重複して数えません。
- 保護者: PINから入り、目標分数・効果音・アバターのリセット、名前、返信、項目、記録削除、バックアップを設定します。目標は既定30分、効果音は既定オンです。

iPad縦向きではプレイヤー、盤面、記録ボタンを上から並べます。横向きではプレイヤーと操作を左、盤面を右に置きます。下部ナビはホームと図鑑だけです。「視差効果を減らす」設定では演出をフェードに切り替えます。

EXPは記録1件で10、自分からで5、疑問で5、写真で2を加算します。累計50でLv.2、150でLv.3、300でLv.4です。EXP自体は保存せず、削除時も記録から再計算します。

複数項目は行ごとに1件の記録として、同じIndexedDBのreadwriteトランザクションで保存します。共通入力は選択順の最初の1件だけに付け、追加EXPと写真の重複を防ぎます。保存演出とリザルトは1回です。獲得EXPは今回の全件、今日の合計時間は当日の全件を集計します。マスは同日なら1枚です。

ストリークは連続して記録した日数です。同日の複数記録は1日と数えます。今日が未記録なら昨日までの連続を表示します。最終記録が一昨日以前なら0日です。週の炎は記録した日だけ点灯します。

ホームは午前0時とアプリへ戻った時に日付を確認します。日付が変われば目標・ストリーク・相棒を更新します。入力中はシートを閉じてから更新します。相棒の名前を取得中に月が変わった場合は、前月へ保存せず、今月の選択に戻ります。

## ローカルで開く

空きポートを確認し、このフォルダで次を実行します。

```sh
python3 -m http.server 8794 --bind 127.0.0.1
```

このMacのブラウザで `http://127.0.0.1:8794/` を開きます。Macのサーバはファイルを配るだけで、記録はブラウザ内で処理します。iPadから試す場合は同じWi-Fiにつなぎ、`scripts/serve-lan.sh <空きポート>` で起動して表示されたLAN内URLを開きます。

LAN内IPのHTTPではService Workerが動きません。iPadでのホーム画面追加とオフライン利用はHTTPSで確認してください。配信元が変わると保存領域も変わります。

## データとバックアップ

記録、写真、選んだ絵、項目、PIN、返信は端末のブラウザ内のIndexedDBに保存します。候補の画像はPokeAPIの公式アート配信元、日本語名はPokeAPIから実行時に取得します。選んだ画像はIndexedDBに保存し、オフラインでも表示します。アカウント同期はありません。

保護者画面からJSONを書き出せます。読み込みは形式を検証し、確認後に全データを置き換えます。従来の形式と月の画像・手描きデータも読み込めます。ブラウザのデータ消去や端末故障に備え、定期的に別の場所へ保存してください。

今月の旧形式（image／drawing／default）は相棒未選択として扱います。選択確定で今月の絵だけを置き換えます。過去月の絵と記録は残ります。同時タブの選択はIndexedDBのトランザクションで1件だけ確定します。設定は`settings`の`adventure`に保存し、バックアップ形式2を維持します。アバターの完成条件が失われた場合は今月の相棒へ戻ります。

効果音は端末のWeb Audio APIで合成します。音源ファイルは使いません。ユーザー操作でAudioContextを開始・再開します。音声が使えない環境でも記録を保存できます。

写真は長辺1280px以下のJPEGに縮小します。「60分以上」は集計上60分です。PINは簡易な入室制限で、暗号化ではありません。HTTPSではSHA-256、Web Cryptoがない環境では従来の簡易ハッシュを使います。SHA-256のPINはLAN内HTTPでは確認できません。

## 開発確認

画面検査の前に、別のターミナルで `python3 -m http.server 8794 --bind 127.0.0.1` を起動します。検査後はサーバを停止します。

```sh
node --test tests/
for f in $(rg --files -g '*.js' -g '*.mjs'); do node --check "$f"; done
node scripts/browser-check.mjs
node scripts/multi-record-check.mjs
node /Users/kazuyaegusa/KEWORK/design_uiux/tools/check/uiux_check.mjs http://127.0.0.1:8794/
```

単体テストは日付、開放順、月集計、EXP、連続記録、バッジ、盤面の全領域、バックアップ互換を検証します。

画面テストは820×1180と1180×820の一時ブラウザを使います。実際のPokeAPI画像と名前を取得し、今月の旧画像から選択、3日分の保存、演出、リザルト、図鑑、設定を確認します。返信、PIN、復元、オフライン、同時タブ、完成と動きを減らす設定も検査します。検査データは一時ブラウザ内だけに作ります。Playwright、axe-core、Chromiumのパスは`PLAYWRIGHT_ROOT`と`CHROMIUM_PATH`で指定できます。URLと画像保存先はスクリプトの第1・第2引数で指定します。

`multi-record-check.mjs`は外部通信を遮断し、検証用の画像で複数行の保存を確認します。行の追加・削除、各分数、共通入力、EXP、合計時間、日単位のマス、連続日数、保存失敗時の全件取消、バックアップ復元、オフライン再読込を検査します。

画面処理は`js/app.js`、盤面は`js/ui/board.js`、演出は`js/ui/effects.js`、相棒は`js/ui/companion.js`、音は`js/ui/sound.js`です。Service Workerは全モジュールを`mainichi-shell-v18`にキャッシュします。
